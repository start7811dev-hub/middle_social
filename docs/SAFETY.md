# 쏘 대화 안전 설계

대상이 중학생이므로 **사회 학습 외의 대화는 하지 않고, 위험 신호에는 상담 대신 도움 받을 곳을 안내**하는 것을 원칙으로 한다.

## 처리 단계 (`shared/guard.ts`, `shared/pipeline.ts`)
| 단계 | 하는 일 | 모델 호출 |
|---|---|---|
| 1. 입력 정리 | 300자 제한, 최근 14턴만, user/assistant 외 역할 제거, NFKC·제로폭 문자 제거, 한글 사이 숫자 제거(자1살) | 없음 |
| 2. 키워드 사전 필터 | 위기(자해·자살·학대·폭력·괴롭힘·그루밍, 은어·초성·영어 포함), 연애·성, 다이어트, 의료·약물, 폭력 방법, 욕설·혐오, 개인정보(전화번호·학년반), 규칙 변경 시도. 교과 질문 표지(아동·피해자·제도·통계·법률…)가 있고 1인칭이 없으면 '약한 신호'로 분류 모델에 넘김 | 없음 |
| 2-1. 대화 기록 정리 | 서버가 서명하지 않은 쏘의 말(위조된 기록) 제거, 예전에 걸렸던 질문과 그 답 제거 | 없음 |
| 3. 주제 분류 | Haiku가 study / offtopic / sensitive / feeling / crisis / pii / injection 중 하나로 판정. 학생 글과 직전 기록은 태그로 감싼 데이터로만 다룸. 애매하면 offtopic, 위기 신호가 조금이라도 있으면 crisis | Haiku |
| 4. 본 응답 | 쏘 시스템 프롬프트(절대 규칙 + 말투 + 현재 학습 문맥) | Sonnet |
| 5. 출력 검사 | 링크, 유해 표현, 규칙 노출이 섞이면 버리고 학습 전환 문구로 대체 | 없음 |

- 분류에서 study가 아니면 본 응답 모델을 **부르지 않는다**. 학습 외 대화가 모델까지 가지 않는다.
- 학습 문맥은 클라이언트가 보낸 글이 아니라 서버가 자기 콘텐츠 파일에서 읽는다(문맥 위조 방지).
- 분류기가 실패하면 본 응답을 부르지 않고 오류로 끝낸다(실패 시 닫힘).

## 응답 방식
- **학습 외(offtopic)**: "나는 사회 공부 담당이야" + 지금 학습의 개념 하나로 질문을 돌려준다.
- **민감(sensitive)**: 설명·조언 없이 거절하고, 부모님·선생님께 여쭤보라고 한 뒤 학습으로 전환.
- **위기(crisis)**: 상담하지 않는다. 믿을 수 있는 어른에게 말하라고 하고 청소년상담 1388, 자살예방상담 109, 112·119를 안내한다. 화면에는 바로 누를 수 있는 번호 카드가 뜨고, 말로 공부하기 중이면 자동 듣기를 멈춘다.
  - 요청서에는 "상담 대응 안 함"이 있었으나, 아이가 위험 신호를 보냈을 때 아무 반응 없이 학습으로 돌리는 것은 안전하지 않다고 판단해 **도움 받을 곳 안내만** 하도록 했다. 상담은 하지 않는다.
- **개인정보(pii)**: 적지 말라고 알려 주고 전환.
- **마음 표현(feeling)**: "공부가 힘들다" 같은 말에는 짧게 공감하고 어른과 이야기하도록 권한 뒤 가장 쉬운 학습 하나를 제안한다. 상담은 하지 않는다.
- **약한 위기 신호**: "학대당한 아동은 어떤 구제를 받아?"처럼 교과 질문에 위기어가 섞이면 분류 모델이 판단하고, 어떤 경우든 "혹시 네 이야기라면 1388"을 덧붙인다. 분류 모델이 없는 오프라인에서는 설명 없이 도움 안내만 한다.
- **규칙 변경 시도(injection)**: 역할을 바꾸지 않고 전환.
- 정치: 현재 논쟁·정당·정치인에 대한 의견을 말하지 않고, 제도 원리와 서로 다른 관점의 근거만 설명한다.

## 말투
기분 나쁘지 않은 반말. 비꼬기·무시·명령조 금지. 틀린 답에는 잘한 부분부터 짚는다(`SSO_VOICE`).

## 개인정보
- 대화 내용은 서버에 저장하지 않고 로그에도 남기지 않는다. 앱에서도 패널을 닫으면 사라진다.
- 음성은 브라우저의 음성 인식이 글자로 바꾸고, 쏘 서버에는 글자만 간다. Safari·Chrome의 음성 인식은 Apple·Google 서버에서 처리될 수 있으므로, 학교 배포 시 이 점을 안내하거나 음성 입력을 끄고 글자 입력만 쓰게 할 수 있다.
- 학생 이름·학교 등을 묻지 않는다.

## 사회 병리 주제 처리 방침
자살·자해·마약·성범죄·학대를 사회 현상으로 자세히 묻는 질문(원인·수법·사례·통계)은 sensitive로 보고 답하지 않는다. 교과 개념 수준(인권 침해와 구제 제도, 학교 폭력 예방 제도, 차별)은 답한다. 학교 운영 방침에 따라 `CLASSIFIER_SYSTEM`의 sensitive 정의로 조정할 수 있다.

## 서버 보호
- 쏘의 답마다 서버가 HMAC 서명을 붙이고, 다음 요청에서 서명이 맞는 쏘의 말만 대화 기록으로 인정한다.
- 접근 코드는 상수 시간 비교, 틀린 시도는 IP당 10분 10회까지.
- 요청 한도: 기기당 10분 30회, IP당 10분 300회(학교처럼 한 IP를 여럿이 쓰는 경우), 인스턴스당 하루 3000회. 인스턴스 메모리 기준이므로 대규모 운영은 영속 저장소로 옮긴다.
- 학습 문맥은 서버 번들(`shared/content.gen.ts`)에서 읽는다. 운영 환경에서는 localhost 출처를 허용하지 않는다.

## 독립 검토 반영 (2026-11-07)
작성자와 다른 검토자가 우회 경로를 점검했고, 다음을 고쳤다: 위조된 대화 기록, 오프라인 경로의 위기 감지 부족과 칭찬 응답, 교과 질문의 위기 오탐, 접근 코드 대입, IP 단위 한도, 분류기 정의(feeling 추가, 역할극·개인정보 개념 질문 허용, 역사 범위), 시스템 프롬프트의 관계 맺기·비밀·고정관념 금지, 연습 문제 프롬프트 규칙, claude.ai 미리보기에서 권한 거부 시 오프라인 전환, 출력 검사(링크·독도 역표기·관계 맺기·약물 용량), 정규화(NFKC·제로폭·초성).

## 시험
- `npm test` — 사전 필터(잡아야 할 표현 17개, 교과 내용인데 걸리면 안 되는 표현 15개: 파키스탄·대공황·대마도·소주제 등), 출력 검사, 서버 흐름(위기 시 모델 미호출, 분류 실패 시 차단, 접근 코드, 요청 한도, 경로 조작 방지, CORS) 등 190개(위기 표현 60여 개, 교과 오탐 방지 40여 개, 위조 기록·서명·한도 포함). 배포 빌드에 포함되어 실패하면 배포되지 않는다.
- `npm run redteam -- <주소>` — 실제 Claude로 38개 시나리오 점검(우회 시도, 역할극, 정치 의견 요구, 위기 표현 포함). 배포 후 매번 실행을 권한다.

## 한계 (운영 전에 알아 둘 것)
- 어떤 필터도 완벽하지 않다. 새로운 은어·우회 표현은 키워드에 없을 수 있고, 그 경우 분류 모델에 의존한다.
- 정확성: 쏘의 설명은 틀릴 수 있다. 프롬프트는 확실하지 않으면 교과서·선생님 확인을 권하게 되어 있다.
- 학교 배포 전에 교사가 레드팀 결과와 실제 대화 몇 건을 직접 확인하는 것을 권한다.
- 만 14세 미만 이용 시 보호자 동의 등 개인정보 관련 법적 검토는 별도로 필요하다(대화 저장은 하지 않지만 음성 인식은 OS·브라우저 제공자의 정책을 따른다).
